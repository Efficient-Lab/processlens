## 总体结论

PRD 的功能边界（只观察、不归因、不吓唬用户）定义得很干净，七个面板与 Summary 五区块的骨架方向正确，"行为账单"定位与 NFR-4.1/AC-3 的验收口径一致。但从交互完整性看，**需求稿目前只描述了"顺利路径的静态内容"，几乎没有描述状态机**：

1. **授权链是双扩展 + FDA 的三段式状态机**（FR-6.1/6.2），是 macOS 上失败率最高的环节，但 FR-6.5 只规定"展示状态 + 不静默降级"，未定义部分就绪、被拒绝、被撤销、需重启等中间态的交互语义，也未定义监控中途权限失效时 Session 如何处理。
2. **核心流程缺三个进行态视图**：监控中（Live 态）、等待目标 App 启动、空 Session，目前七个面板全部面向"已生成的报告"。
3. **"Observed sequence, not proof of upload"（FR-5.9）作为唯一防误读手段过于单薄**：它是英文单句、未规定展示位置、未覆盖导出场景，且 Timeline Correlation 区块的"→"视觉本身就在暗示因果，与文案互相打架。流量数字（上传/下载量）同样存在被普通用户误读为"上传了我的文件"的风险。
4. **信息架构上 Export 是一个动作而非内容面板**，Home 与 Summary 的层级关系（Summary 属于哪个 Session）未定义，监控进行态在 IA 中没有位置。

总体上这是一份"内容定义充分、状态定义不足"的 PRD。建议在 G3（UX Gate）之前补齐交互状态机与文案规范，否则 G3 验收"非安全专业用户可看懂"时缺乏可执行的判定依据。

## 交互缺口清单

按核心流程"选 App → 授权 → Start → 使用 → Stop → 看报告"逐步推演，覆盖 PRD 未定义的交互状态：

| 编号 | 严重度 | 场景/状态 | 当前覆盖 | 建议 |
|------|--------|-----------|----------|------|
| UX-01 | 高 | 授权部分就绪：Endpoint Security 已激活但 Network Extension 未激活，或 FDA 未授予 | FR-6.5 只要求"展示权限状态与引导、不允许静默降级"，未定义部分能力可用时能否 Start | 定义三档就绪度：完全就绪 / 部分就绪（明示缺失能力，用户显式确认后可 Start，报告中标注"未覆盖网络/文件"）/ 未就绪（禁用 Start）。禁止默认放行部分采集 |
| UX-02 | 高 | 授权被拒绝、扩展被用户移除、FDA 事后被撤销、激活后需重启 | FR-6.5 未覆盖失败态与恢复路径 | 为每个失败态定义恢复 CTA：跳转系统设置对应面板、重新触发激活请求、重启提示文案；权限状态需每次启动时重新检测而非只在首次 onboarding |
| UX-03 | 高 | 监控进行中权限失效或系统扩展崩溃 | FR-2.4 只覆盖"采集端崩溃后数据可恢复"，未定义 Session 语义：是终止、暂停还是产生数据缺口 | Session 增加 interrupted 状态；报告中明确标注数据缺口区间（"14:02–14:15 采集中断"），恢复后可继续同一 Session |
| UX-04 | 高 | Start 后目标 App 始终未启动 | FR-2.3 覆盖进程退出/重启不中断 Session，但"等待启动"这一进行态无任何 UI 定义 | 监控态增加"等待目标 App 启动"状态：采集已就绪、事件计数为 0、持续提示；避免用户误以为工具失效 |
| UX-05 | 高 | Timeline Correlation 的因果误读 | FR-5.9 仅规定一句英文免责声明，未规定位置、语言、导出传播；视觉上"READ → outbound"的箭头本身暗示因果 | 免责声明需本地化并逐条就近展示（非页脚一次性声明）；导出的 JSON/CSV/Markdown 内嵌同样声明；视觉用时间轴并列呈现取代"→"箭头 |
| UX-06 | 高 | "上传/下载量"被误读为"上传了用户文件" | FR-5.2/FR-4.1 直接展示 bytes up/down，无任何限定语 | Summary 流量数字必须配副标题"网络流量元数据，不含传输内容"；Network 面板列表头同样标注 |
| UX-07 | 中 | 监控中切换目标 App | FR-1.6 禁止同时监控两个 App，但未定义监控中改选的交互 | 监控中锁定 App 选择器；改选需先 Stop，并提示当前 Session 会被结束并生成报告 |

| UX-09 | 中 | 事件量过大（UC-2：启动即写数千文件） | NFR-1.1 只要求"UI 不卡死"，无展示策略 | 列表虚拟化渲染；聚合视图截断并提示"已聚合 N 条，显示 Top 100"；监控中 UI 降采样刷新 |

| UX-11 | 中 | 监控进行态（Live 视图）缺失 | 七个面板全部面向已生成报告，监控中用户看什么、是否实时刷新均未定义 | 定义 Live 态：Session 详情页复用 Summary/Files/Network 结构实时刷新，顶部常驻录制指示、已采集事件计数与 Stop 按钮 |

## 信息架构评估

### 结构判断

Home / Summary / Files / Network / Timeline / Processes / Export 七个面板覆盖了核心流程的内容需求，但存在四个结构性问题：

**1. Export 是动作，不是面板（中）**

Export 不包含可浏览内容，与六个内容面板并列会破坏导航心智模型（用户点开 Export 期待看到内容，实际触发一个操作）。建议改为：Session 详情页顶部的导出按钮 → 格式选择（JSON/CSV/Markdown）→ 敏感信息提示（FR-5.10）→ 保存。FR-5.7 的能力不变，仅改变 IA 位置。

**2. Home 与 Summary 的层级关系未定义（高）**

PRD 把七个面板平级列出，但 Summary 必然属于"某一个 Session"。当前定义下用户无法判断 Summary 展示的是最近 Session、当前 Session 还是需要先选择。建议明确两级结构：

```
Home（选择 App / 权限状态 / Session 列表 / Start）
└── Session 详情（监控中 = Live 视图；已结束 = 报告）
    ├── Summary（默认落地页，行为账单）
    ├── Files / Network / Timeline / Processes
    └── Export（操作入口）
```

即 Summary 等四个内容面板是 Session 详情内的 tab，而非与 Home 平级的顶层导航。这也自然解决了 UX-11 的 Live 态安放问题。

**3. Processes 的角色定位需要写明（低）**

Processes 是归属核对工具（FR-1.5），目标受众是 power user 而非普通用户。保留为 tab 没有问题，但建议：Summary 的敏感/网络条目可显示"由哪个进程产生"并一键跳转到 Processes 对应节点，让核对路径对普通用户也可达，而不是要求用户主动理解归属模型。

**4. Timeline 的双重身份需要区分（低）**

Timeline 既是独立面板（FR-5.5 全量混排+过滤）又是 Summary 内的 Correlation 区块（FR-5.8 时序并排）。建议明确：Summary 内为"相关性摘要"（仅展示文件事件与网络事件时间上相邻的少量样本，带免责声明），点击"查看完整时间线"跳转 Timeline 面板。两者共用数据但视觉密度不同。

### 导航与下钻路径

- 核心下钻链为 **Summary → Files/Network/Timeline**，当前 PRD 未定义区块与面板间的过滤态传递（UX-12），这是"行为账单"定位能否成立的关键——账单的每一行都应该可以查账。
- Files 面板内"路径 / 目录 / 进程"三维聚合（FR-3.4）建议默认目录聚合（信息密度最低、最接近"它碰了哪些位置"的问法），路径与进程维度作为切换项。
- 权限引导（FR-6.5）建议作为 Home 的常驻卡片而非独立页面：权限状态本身就是 Home 的一级信息（FR-5.1 已含），引导卡片按 UX-01/UX-02 的状态机渲染对应文案与 CTA。

## 建议新增/修改的需求条目

以下条目建议并入 PRD 修订版（编号沿用现有体系，新增条目取各模块末位序号）：

### FR-2 Session 生命周期

- **新增 FR-2.6（P0）**：Session 状态模型应包含 `recording / interrupted / completed / empty`；interrupted 与 empty 状态必须在报告中有对应展示，数据缺口需在 Timeline 与 Summary 中标注时间区间。（对应 UX-03、UX-08）
- **新增 FR-2.7（P0）**：GUI 关闭不应中断进行中的 Session；监控期间应提供系统级常驻指示（菜单栏图标 / Dock 角标）与 Stop 入口。（对应 UX-10）

### FR-5 报告与信息架构

- **修改 FR-5.2**：Summary 中上传/下载流量数字必须标注"网络流量元数据，不含传输内容"；敏感路径摘要使用中性视觉语言（中性色、中性图标），禁止警告性视觉暗示。（对应 UX-06、UX-13）
- **修改 FR-5.7**：Export 作为 Session 详情内的操作入口而非顶层面板；触发导出流程为：格式选择 → 敏感信息提示 → 保存。
- **修改 FR-5.9**：免责声明要求扩展为——(a) UI 文案本地化；(b) 逐条就近展示于每组时序关联条目，而非集中声明；(c) 所有导出格式在文件头部内嵌同等声明与 Session 上下文；(d) 视觉呈现使用并列时间轴，不使用暗示因果的箭头连接符。（对应 UX-05、UX-16）
- **新增 FR-5.11（P0）**：Summary 各区块条目应支持下钻，跳转目标面板并预置对应过滤条件（路径 / 域名 / 进程 / 时间范围）。（对应 UX-12）
- **新增 FR-5.12（P0）**：定义空态规范——无 Session、空 Session、单一区块无数据、域名未解析（仅 IP）四类空态均有明确说明文案，不展示空白或零值堆砌。（对应 UX-08、UX-14）

### FR-6 权限与安装

- **修改 FR-6.5**：权限状态机应至少包含 `未安装 / 待系统批准 / 已批准待 FDA / 完全就绪 / 被拒绝 / 被撤销 / 需重启 / 扩展异常`；每档定义 Home 展示文案、Start 可用性与恢复 CTA。部分就绪（文件或网络单侧可用）时 Start 需用户显式确认，且报告须标注采集能力缺口。（对应 UX-01、UX-02、UX-18）
- **新增 FR-6.7（P0）**：监控进行中权限失效或扩展崩溃时，Session 进入 interrupted 状态，不静默停止也不假装正常；恢复后用户可选择继续当前 Session 或结束。（对应 UX-03）
- **新增 FR-6.8（P0）**：应用内提供系统扩展/特权服务的移除引导，作为干净卸载（FR-6.6）的用户可达路径。（对应 UX-20）

### FR-1 应用选择

- **新增 FR-1.7（P1）**：已安装应用列表之外，应支持手动指定目标（拖入 .app、选择可执行文件、输入 Bundle ID），覆盖 CLI 工具与非标准安装路径。（对应 UX-15）
- **新增 FR-1.8（P0）**：监控进行中目标 App 选择器锁定；改选目标需先结束当前 Session。（对应 UX-07）

### NFR-4 可用性

- **新增 NFR-4.3（P0）**：监控进行中应提供实时反馈：录制指示、已采集事件计数、目标 App 运行状态（运行中 / 等待启动）。（对应 UX-04、UX-11）
- **新增 NFR-4.4（P1）**：可访问性与本地化基线——键盘导航、焦点可见、WCAG 2.1 AA 对比度；免责声明、权限引导等关键文案必须随界面语言切换。（对应 UX-19）
- **补充 NFR-1.1 的验收口径**：高事件量场景下前端采用虚拟化渲染与聚合截断，"UI 不卡死"应有可测指标（如 10 万事件 Session 的滚动帧率与内存上限）。（对应 UX-09）

### AC 验收标准

- **补充 AC-3 的可执行口径**：建议以任务式可用性测试验收——非安全专业用户在不展开 raw event 的前提下，能在限定时间内正确回答"碰了哪些重要位置、连了哪些目标"，且**不产生因果性误读**（如把流量数字说成"上传了文件"）。这同时覆盖 UX-05/UX-06 的验证。
- **建议新增 AC-7**：授权流程中任一失败态（拒绝、撤销、部分就绪）均有对应 UI 与恢复路径，无死胡同。
