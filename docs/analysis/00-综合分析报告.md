## 1. 总体结论

**六个视角一致给出 Conditional Pass：需求稿底子好（边界清晰、转译完整、优先级克制），但不能直接进开发。**

各方对优点的判断一致：企划书 P0 范围转译完整（产品/PM 核对 19 章中 12 章全覆盖），"只观察、不归因、全本地"原则在 FR-3.3、FR-4.3、FR-5.9、NFR-2 中形成闭环，未发现擅自扩 scope。

缺口集中在四个结构性问题：

1. **技术前提有误判**（桌面工程师）：§7 有四处实质性乐观表述，其中两项可能推翻 P0 承诺——macOS ES 没有 READ 事件且无字节数、NE flow 元数据不含流量字节；Windows 侧 ETW FileIo 不含路径且无法按 PID 内核过滤。
2. **Go/No-Go 被低估**（桌面工程师 + 项目经理交叉确认）：Network Extension 的 content-filter entitlement 与 ES 同属 Apple 受限审批，G0 实为双申请，当前文档把 NE 写成"确认配置"。
3. **采集器自身无设防**（安全架构师）：IPC 无认证（Critical）、渲染/导出链路无消毒、SQLite 明文无保护、无更新与漏洞响应机制。
4. **状态机与数据治理缺失**（PM/UX/隐私三方收敛）：Session 只有 Start/Stop，无删除、无 interrupted/empty 状态、无权限部分就绪语义；元数据生命周期只覆盖到"展示"，导出脱敏与删除全部缺位。

## 3. 各视角关键发现

### 3.1 产品经理（`01-product-manager.md`，17 项问题：高 4 / 中 7 / 低 6）

- 企划书 §14 的开源建议与 About 品牌入口在 PRD 中静默丢失——免费项目唯一的商业叙事载体。
- Session 管理 FR 全缺（删除、存储上限、重复 Start、目标未运行）。
- 兼容性/最低系统版本矩阵完全缺失。
- 4 条 P0 冻结前必做：Session 管理、性能量化、兼容性矩阵、Windows 分发验收。

### 3.2 桌面工程师（`02-desktop-app-engineer.md`，14 项技术风险 + 13 项缺口）

四处实质误判（事实边界均标注"待实测验证"）：

| 误判 | 影响 |
|------|------|
| ES 无 READ 事件（只能由 OPEN(FREAD) 近似），且无字节数 | FR-3.1/3.2 语义需按平台重写；"读"=以读方式打开 |
| NE flow 元数据不含流量字节数，需 PacketProvider 逐包计数 | FR-4.1 的 bytes up/down 在 macOS 有吞吐成本，或降级为连接数/时长 |
| ETW FileIo 不含路径（FileObject→path 映射是隐藏主体工程）且无法 PID 内核过滤 | §7.2 低估了 Windows 文件侧工程量；NFR-1.2"内核层尽早过滤"在 Windows 不成立 |
| NE entitlement 同为受限审批 | Go/No-Go 双门槛，G0 双申请 |

另给出跨平台字段可得性矩阵，以及 IPC 契约、启动基线快照、路径规范化、归属映射崩溃重建等 13 项工程缺口。重要修正：**Windows P0 用 user-mode WFP + ETW 即可，无需内核驱动，"Windows beta 先行"策略技术可行。**

### 3.3 安全架构师（`03-security-architect.md`，13 项威胁：Critical 1 / High 5）

- **T-01 Critical**：IPC 无认证——Windows 特权服务管道若可被任意本地进程连接，等于 SYSTEM 级数据出口（经典 LPE 类别）。
- 产品层隐私边界扎实，但"不抓 payload"目前只是承诺而非架构保证——需结构性约束（永不返回 filterDataVerdict、采集层无内容读取路径、CI 静态检查）。
- 被监控 App 是潜在对手：恶意文件名/域名可穿透渲染（存储型 XSS→Tauri command）与导出（CSV 公式注入）。
- 交付 11 条 SEC-FR + 2 条 SEC-NFR 可直接并入 PRD 的条目草案。

### 3.4 隐私工程师（`04-privacy-engineer.md`，11 项风险：高 4）

- 采集侧最小化到位，但元数据生命周期只覆盖到"展示"：删除、保留、脱敏、特权层日志边界全缺。
- 特权采集层先见全系统事件再过滤——非归属事件"不持久化、不进日志、不进崩溃转储"需写成隐私条款而非性能条款。
- 建议新增 FR-7 数据治理组（9 条，P0 为主）+ AC-7~9 验收（删除可验证、导出脱敏、应用自身零外联可枚举）。
- 建议收紧 NFR-2.2：P0 不内置遥测；"可选遥测"口子在 GitHub/HN 受众中是信用减分项。

### 3.5 UX 架构师（`05-ux-architect.md`，20 项交互缺口：高 6）

- 授权链是三段式状态机（双扩展 + FDA），目前只有"展示状态"要求，无部分就绪/失败/撤销/需重启的语义。
- 核心流程缺三个进行态视图：监控中 Live 态、等待目标启动、空 Session。
- IA 建议：Export 降级为 Session 详情内操作入口；明确 Home → Session 详情两级结构（Summary 等四面板为详情内 tab）。
- 免责声明需本地化、就近逐条展示、导出内嵌；"→"箭头改为并列时间轴。

### 3.6 项目经理（`06-senior-project-manager.md`，14 项风险：高 4）

- Go/No-Go 无时间阈值：建议 G0 提交后 T+90 天首次评审、T+180 天未获批触发正式 No-Go 评审。
- Gate 验收语普遍缺度量（G1"数据可信"、G3"可看懂"、G4"可持续使用"均不可判定）。
- 约 30 条需求无阶段归属，已给出全部 P0 需求的 G1–G4 建议映射表。
- 项目管理要素缺失：变更管理（P0 冻结点建议 G2）、版本与更新策略、Windows 签名证书外部依赖。

### G1 专项验证项（实测前不定案）

- macOS 包级流量通道（PacketProvider）吞吐成本 → 决定 bytes 是 P0 还是降级
- Windows FileObject→path 映射准确率 → 决定文件路径链路方案（备选 minifilter 驱动，成本上升）。**部分已实测（2026-09-27，`08` 文档）：通道与字段结构确认，Read/Write 族仅 FileObject+IOSize 无路径；准确率与过滤成本留 PoC**
- ES 在无 FDA 下的事件盲区 → 决定 FDA 是硬依赖还是推荐授权
- entitlement 未获批时 macOS PoC 可开发路径（dev-signed / SIP 降级 / 虚拟机）→ **07 文档已实测：无降级路径，exec 即被杀**

### 下一轮修订（非阻塞）

- 空态/错误态 FR 全集；Settings 入口（敏感路径默认列表）；Summary 区块下钻；Windows App 枚举归一模型
- 需求-阶段映射表落入 §10；变更管理条款（P0 冻结点）
- 决策项：开源范围、About 品牌入口、自动更新策略——显式记录为决策项而非静默丢失
