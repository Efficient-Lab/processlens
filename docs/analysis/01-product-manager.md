## 总体结论

PRD 对企划书的转译整体质量较高：产品边界（只观察不拦截、不做安全结论、全本地）在 §1.3、§8、NFR-2 中层层落实且口径一致；归属模型、信息架构、数据模型、风险与 Gate 几乎全部一一映射；P0/P1 划分与企划书原文一致，没有发现擅自扩 scope 的条目。这是一份"底子好、但还不能直接进开发"的稿子。

主要缺口集中在四类：**(1) Session 管理与状态机不完整**——FR-2 只有 Start/Stop 生命周期，没有删除、存储上限、重复 Start、目标未运行等边界定义；**(2) 关键 NFR/AC 不可测试**——"不明显拖慢""无丢失性故障"无法验收；**(3) Windows 侧系统性偏弱**——P0 平台却没有安装形态、签名分发、专属 AC，且流量字节采集在 WFP ALE 层存在可行性疑问；**(4) 企划书 §14 的开源建议与品牌入口未转译**——这是免费项目唯一的商业叙事载体，不应在 PRD 中静默丢失。

建议：**修订后可进入开发（Conditional Pass）**。优先补齐高严重度问题后再冻结 P0 范围。

## 修改建议清单（按优先级排序）

1. **【P0 冻结前必做】补 Session 管理 FR**：删除（单个/全部）、存储上限与超限行为、重复 Start 拦截、目标未运行时的 Start 语义（PM-01、PM-05）。
2. **【P0 冻结前必做】量化 NFR-1 与 AC-4**：给出 CPU 增量、内存、UI 响应、事件丢失率的可测阈值，并把丢失计数纳入报告展示（PM-02、PM-07）。
3. **【P0 冻结前必做】新增兼容性 NFR**：macOS / Windows 最低版本矩阵及各采集能力的版本依赖（PM-03）。
4. **【P0 冻结前必做】补 Windows 分发与验收**：代码签名策略、特权服务安装/提权流程、卸载清理 FR，加至少 1 条 Windows 专属 AC（PM-04）。
5. **【G1 spike】验证两个技术前提**：Windows WFP 字节级流量统计可行性（PM-11）；ES 在无 FDA 下的路径覆盖盲区（PM-16）。结果回写 FR-4.1 / FR-6.1。
6. **【下一轮修订】补空态/错误态 FR**：零事件报告、采集失败标记、权限被拒引导、磁盘写满与数据损坏处理（PM-06）。
7. **【下一轮修订】补 Settings 入口 FR**：敏感路径默认列表（沿用企划书 §12 示例）+ 用户可配置项（PM-08）。
8. **【下一轮修订】明确 Windows App 枚举与归一模型**（PM-09）。
9. **【决策记录】开源范围与 About 品牌入口**：作为显式决策项写入 PRD 附录或 Open Questions，不要静默丢失（PM-10、PM-14）。
10. **【文字修订】逐条消歧**：FR-3.2 bytes 存在条件、FR-2.1/§6 version 指代、FR-5.5 过滤维度、FR-5.7 冗余措辞、第 12 行上游文件名、补更名说明（PM-12、PM-13、PM-15）。
11. **【补齐 AC】导出正确性、崩溃恢复（FR-2.4）、卸载干净（FR-6.6）各补一条验收**（PM-04 关联）。
12. **【显式排除】自动更新机制标注为不做或 P1+**（PM-17）。
